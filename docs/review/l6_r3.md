# Review: L6 R3, the Windows package

Status: 2026-10-29. Reviewer: Opus. Scope: the uncommitted R3 of `docs/design/l6_release.md` section 4 with the
decisions of 7 (per-user installer, console twin installed as `cuboid.com`): `xtask/{Cargo.toml,src/package.rs}`,
`packaging/{Packager.toml,installer.nsi,THIRD-PARTY-NOTICES.txt}`, `.github/workflows/release.yml`,
`crates/cuboid-app/{Cargo.toml,build.rs}`, `crates/cuboid-term/{Cargo.toml,build.rs}`, the
`[workspace.dependencies]` lines of `Cargo.toml`, `Cargo.lock`, `crates/cuboid-assets/brand/cuboid.ico`.
`xtask/src/main.rs` is unchanged (the `package` entry existed). The R2 changes in `cuboid-shell` and `cuboid-app/src`
are not reviewed. Read against the cargo-packager 0.11.8 source in the cargo registry (`src/package/nsis/installer.nsi`
and `mod.rs`, `src/cli/config.rs`, `src/config/mod.rs`), the NSIS 3.09 toolset it downloaded
(`%LOCALAPPDATA%\.cargo-packager\NSIS`: MUI2 `Pages/Finish.nsh` and `Pages/StartMenu.nsh`, the reference in
`NSIS.chm`, `makensis -HDRINFO`), winresource 0.1.34 `lib.rs`, and the script cargo-packager rendered from the template
for the coordinator's build (`target/package/.cargo-packager/nsis/x64/installer.nsi`, UTF-16).

Run (see Gates): `cargo clippy -p xtask -p cuboid-term --all-targets -j 4 -- -D warnings` (clean), `cargo xtask
layering` (ok, 28 crates), `cargo metadata --locked --format-version 1` (exit 0), `rustfmt --check` of the three Rust
files (clean), an LF/BOM check of the seven text files. Read-only probes of the coordinator's output: the version
resources of the staged `cuboid.exe`, `cuboid.com` and the setup, the icons extracted from the release binaries, the zip
listing, the rendered NSIS script, a `diff` of `installer.nsi` against the upstream template. Not run: the installer,
a release build, the GUI, the workspace tests.

Verdict: ready after one major and the minors. The package does what section 4 asks: the icon is rendered from the
masters, embedded with a version resource in both programs on Windows only, the installer is per user with no
elevation, a Start menu entry, an uninstaller, the guide and the licences, the association is opt-in and off by
default, the zip is portable and reproducible, both names carry the version, and CI drafts and never publishes. The
association code writes the right keys but its uninstall side removes more than cuboid wrote, and an upgrade drops it.
Nothing here blocks a draft; the third-party notices (7) and the final identifier block a published release.

## Major

1. `packaging/installer.nsi:663-664` with `:597-602`. When the box is ticked, `AssociateCubik` overwrites the default
   value of `HKCU\Software\Classes\.cubik` without keeping the ProgID it replaces, and the uninstaller deletes the
   whole `.cubik` key whenever that default is `cuboid.cubik`. The key is shared: Explorer and other programs keep
   values and subkeys in it (`OpenWithProgids`, `ShellNew`, `PerceivedType`). A user whose `.cubik` files opened in
   Cubik Studio through a per-user registration (the users this editor is for) loses that association for good once
   cuboid is uninstalled; only a machine-wide one under HKLM comes back. That is a side effect nobody asked for, and
   "removes only what it wrote" does not hold. Upstream's `FileAssociation.nsh`, which the template still includes,
   keeps a `<class>_backup` value for exactly this. Fix: at the top of `AssociateCubik`

   ```nsis
     ReadRegStr $R0 SHCTX "Software\Classes\.cubik" ""
     ${If} $R0 != "cuboid.cubik"
       WriteRegStr SHCTX "Software\Classes\.cubik" "cuboid.backup" $R0
     ${EndIf}
   ```

   plus `WriteRegStr SHCTX "Software\Classes\.cubik\OpenWithProgids" "cuboid.cubik" ""` beside the other writes, and
   in place of `:597-602`

   ```nsis
     ReadRegStr $R7 SHCTX "Software\Classes\.cubik" ""
     ${If} $R7 == "cuboid.cubik"
       ReadRegStr $R8 SHCTX "Software\Classes\.cubik" "cuboid.backup"
       ${If} $R8 == ""
         DeleteRegValue SHCTX "Software\Classes\.cubik" ""
       ${Else}
         WriteRegStr SHCTX "Software\Classes\.cubik" "" $R8
       ${EndIf}
     ${EndIf}
     DeleteRegValue SHCTX "Software\Classes\.cubik" "cuboid.backup"
     DeleteRegValue SHCTX "Software\Classes\.cubik\OpenWithProgids" "cuboid.cubik"
     DeleteRegKey /ifempty SHCTX "Software\Classes\.cubik\OpenWithProgids"
     DeleteRegKey /ifempty SHCTX "Software\Classes\.cubik"
     DeleteRegKey SHCTX "Software\Classes\cuboid.cubik"
     System::Call 'Shell32::SHChangeNotify(i 0x8000000, i 0, i 0, i 0)'
   ```

   In NSIS 3.09 `/ifempty` removes a key only when it has neither subkeys nor values (`NSIS.chm` 4.9.2.3). The
   `OpenWithProgids` value keeps cuboid in Open with when the user picked another program through Windows' own
   UserChoice, which no installer may override. The notify makes Explorer drop the cuboid icon on `.cubik` files at
   once; today only the install side sends it (`:668`). Check after the fix: a preset `.cubik` default `Other.cubik`
   and an `OpenWithProgids\Other.cubik` value survive an install with the box ticked and an uninstall, and the default
   is `Other.cubik` again.

## Minor

2. `packaging/installer.nsi:281` (upstream) with `:597-602` and `:325`. An upgrade through the window loses the
   association. For a different version the reinstall page selects "Uninstall before installing" by default
   (`:197-202`, `:242-243`), which runs the old uninstaller (`ExecWait '$R1 /P _?=$4'`), which removes the association;
   the new finish page then offers the box unticked. A user who ticked it once has to tick it at every update. Silent
   and passive updates keep it (they skip that page, so nothing is uninstalled). Fix: remember the state before the
   reinstall page and pre-tick the box.

   ```nsis
   Var CubikWasOurs
   ; in .onInit, after !insertmacro SetContext
     ReadRegStr $0 SHCTX "Software\Classes\.cubik" ""
     ${IfThen} $0 == "cuboid.cubik" ${|} StrCpy $CubikWasOurs 1 ${|}
   ; before !insertmacro MUI_PAGE_FINISH
   !define MUI_PAGE_CUSTOMFUNCTION_SHOW FinishShow
   Function FinishShow
     ${IfThen} $CubikWasOurs == 1 ${|} ${NSD_Check} $mui.FinishPage.ShowReadme ${|}
   FunctionEnd
   ```

   `$mui.FinishPage.ShowReadme` is the checkbox MUI2 creates (`Pages/Finish.nsh:55`, `:386`). A first install still
   shows it unticked.
3. `packaging/installer.nsi:517`, `:313` and `:621-634`. The uninstaller leaves `HKCU\Software\cuboid\cuboid`, whose
   default value is the install folder (written at `:517`; uninstall deletes only its `Installer Language` value at
   `:634`), and the parent `HKCU\Software\cuboid` (the publisher is the second part of the identifier,
   `config/mod.rs:1844-1851`). It also leaves the Start menu shortcut whenever the user typed another folder on the
   Start menu page: no `MUI_STARTMENUPAGE_REGISTRY_*` is defined, so `MUI_STARTMENU_GETFOLDER` at `:621` returns the
   default name, not the chosen one (`Pages/StartMenu.nsh:174-187`). The smoke test's "no key left" looked at the
   uninstall key; `reg query HKCU\Software\cuboid` after the next run shows the rest. Fix: before `:313`

   ```nsis
   !define MUI_STARTMENUPAGE_REGISTRY_ROOT "HKCU"
   !define MUI_STARTMENUPAGE_REGISTRY_KEY "${MANUPRODUCTKEY}"
   !define MUI_STARTMENUPAGE_REGISTRY_VALUENAME "Start Menu Folder"
   ```

   and in place of `:634` (after the shortcut lines, which read the value first)
   `DeleteRegKey HKCU "${MANUPRODUCTKEY}"` and `DeleteRegKey /ifempty HKCU "Software\${MANUFACTURER}"`. An upgrade
   still finds a custom folder: `.onInit` and the reinstall page read it before the old uninstaller runs. HKCU is right
   because this template is only used per user.
4. `docs/mcp.md:29-33` and `:137-139`, installed as `docs\mcp.md`. The guide inside the package opens section 2 with
   "There is no installer yet" and tells the reader to build the repository and copy both programs; the update
   paragraph says to copy or build them again. Fix: replace the first sentence and a half with "The Windows installer
   puts `cuboid.exe` and its twin `cuboid.com` in `%LOCALAPPDATA%\cuboid` (no administrator rights); the zip keeps
   them in the folder you extract it to. A build of the repository works too: run ... and copy ..., naming the second
   one `cuboid.com`.", and at `:138` "run the installer of the new version, or copy or build ...". Keep the example
   paths: `crates/cuboid-mcp/tests/guide.rs:17-18` pins `C:\Program Files\cuboid\...` to what `Snippets` gives.
5. `xtask/src/package.rs:91-99` with `:262-268`. Without cargo-packager in `target/tools/bin` or on the path,
   `cargo xtask package` prints a hint and exits 0 with no installer, although `--no-installer` exists to skip it on
   purpose. Whoever reads the exit code believes the release is complete; in CI the gap shows only when
   `gh release create` cannot find a literal `target/package/*-setup.exe`. Any spawn error, not only "not found",
   counts as "not installed". Fix: `installer` returns `Result<PathBuf, _>`, and the `Err` of the `--version` spawn
   becomes `Err(format!("cargo-packager {PACKAGER_VERSION} is not installed ({err}); install it with `cargo install
   cargo-packager --locked --version {PACKAGER_VERSION} --root target/tools`, or pass --no-installer"))`.
6. `.github/workflows/release.yml:25`, `:30`, `:46`. Three hardening points in the only workflow with a write token:
   - `actions/checkout@v4` keeps `persist-credentials: true`, so the `contents: write` token sits in `.git/config` for
     every later step: the build scripts of `cargo install cargo-packager` and of the workspace, and the third-party
     `Swatinem/rust-cache`. Only `gh` needs it, and it gets it from `GH_TOKEN`. Fix: `with: { persist-credentials:
     false }` on the checkout.
   - `Swatinem/rust-cache@v2` cannot help here: its key carries the job id (`windows`), which no `ci.yml` job writes,
     and a tag run restores only caches of its own ref and of the default branch. It never hits, and its post step
     stores a cache per tag in the repository's 10 GB budget, evicting the caches `ci.yml` relies on. Fix: drop the
     step, which also removes the only third-party action from the job.
   - `cargo xtask package` is `cargo run --package xtask --` without `--locked` (`.cargo/config.toml:2`). With a stale
     lock file that first build rewrites `Cargo.lock`, and the inner `cargo build --locked` (`package.rs:173`) then
     passes against the rewritten file. Fix: `run: cargo run --locked -p xtask -- package`.

   The `permissions` block itself is minimal (`contents: write` is what drafting needs), and the tag reaches the shell
   as `$GITHUB_REF_NAME`, never through a `${{ }}` expansion.
7. `packaging/THIRD-PARTY-NOTICES.txt:1-5`. Acceptable as a placeholder for a draft, which distributes nothing; not for
   the published release. The MIT, BSD and Apache-2.0 crates compiled into `cuboid.exe` and the embedded Inter font
   (OFL-1.1, whose licence must accompany every copy) need their notices in the package, and nothing stops a hand
   publication of the draft. Fix now: `release.yml:53` adds `--notes "Not for publication:
   THIRD-PARTY-NOTICES.txt is a placeholder."` (the API puts a given body before the generated notes), and
   `package.rs` prints a warning while the file still contains "placeholder". Before the first publication: implement
   `cargo xtask licences` (a stub, `xtask/src/licences.rs`) with cargo-about over `cuboid-app` and `cuboid-term` only
   (the xtask crates resvg, ico and zip and the build dependency winresource do not ship), add the Inter OFL text and
   the Phosphor notice listed in `crates/cuboid-assets/THIRD_PARTY.md`, and let `xtask package` run it.
8. `Cargo.toml:143-144` with `xtask/src/package.rs:198-201`. The release profile writes the line tables to
   `target/release/cuboid.pdb` (70 MB here) and the package ships only the executables. A crash report
   (`crates/cuboid-app/src/crash.rs:55`, `Backtrace::force_capture().to_string()`) on a user's machine therefore lists
   `<unknown>` frames, and std's short format prints no address for an unresolved frame, so the report cannot be
   symbolicated later either. On the build machine dbghelp finds the PDB through the absolute path in the executable,
   so a local smoke test does not show it. Fix in R3: `xtask package` also writes
   `cuboid-<version>-windows-x64-symbols.zip` with `cuboid.pdb` and `cuboid_term.pdb`, and `release.yml:54` attaches it
   to the draft (or the owner accepts the size and the PDB ships next to `cuboid.exe`). For the owner of `crash.rs`:
   format the backtrace with `{:#}` (addresses) and add the address of one known function, so frames map to the PDB
   despite ASLR.

## Nit

9. `crates/cuboid-app/build.rs:13-19`, `crates/cuboid-term/build.rs:13-19`. The `rerun-if-changed` lines come after the
   Windows checks, so on Linux and macOS (and on a Windows host building for them) the script prints none and Cargo
   reruns it, and rebuilds the crate, after any change in the package, an integration test included. Fix: print
   `cargo:rerun-if-changed=build.rs` first in `main`, before the `cfg`.
10. `packaging/Packager.toml` sets no `copyright` and no `[windows]`, so the rendered script has `!define COPYRIGHT ""`
    and `!define ALLOWDOWNGRADES ""`. `BrandingText ""` shows NSIS's default "Nullsoft Install System v3.09" under every
    page (`NSIS.chm` 4.8.1.6) and the setup has no LegalCopyright. With downgrades neither "true" nor "false", the
    reinstall page labels its second choice "Downgrading without uninstall is disabled" (`installer.nsi:207-211`) and
    leaves it enabled (`:234-236`). Fix: `copyright = "..."` (a placeholder until D-L2; the same line later goes into
    `LegalCopyright` of both build scripts, logo.md 4) and `[windows]` with `allow-downgrades = true`, today's
    effective behaviour.
11. `packaging/installer.nsi:674`. `ApplicationID::Set` gives the Start menu shortcut the AppUserModelID
    `org.cuboid.cuboid`, which the app never sets for itself, so a window started from the shortcut and one started by a
    `.cubik` double click can sit under separate taskbar buttons, and a pin made from one does not group the other. The
    plugin is also the one file cargo-packager downloads without a hash (`nsis/mod.rs:317`; NSIS and nsis_tauri_utils
    are SHA-1 checked), and it ends up inside the installer. Fix: drop the line.
12. `packaging/installer.nsi:451-480` (upstream). The running check looks for `cuboid.exe` by name, for every user and
    folder: the twin `cuboid.com` (waiting on an editor started from a terminal) is not checked, so its overwrite or
    delete can fail; a portable or development `cuboid.exe` and the `cuboid mcp` servers the AI clients keep open are
    killed as well; a silent install kills without asking (`:455`). Acceptable while the window installer asks first
    and recovery covers the editor; if touched, add `nsis_tauri_utils::FindProcess "cuboid.com"` to the macro.
13. `xtask/src/package.rs`. `workspace_version` (`:121-130`) parses the root manifest for what
    `env!("CARGO_PKG_VERSION")` already is (xtask inherits `version.workspace`); use that and delete the function.
    `:138` loses the path on a missing master; map the error with it as `:204` does. `--debug` (`:190-192`) packages
    the console-subsystem debug binaries under the release names and overwrites a real release package; suffix the
    outputs with `-debug` or refuse `--debug` without `--no-installer`. `:291`: renaming the setup to
    `cuboid-<version>-windows-x64-setup.exe` after packaging gives one naming scheme with the zip (adjust the glob in
    `release.yml:54`).
14. `xtask/src/package.rs:28-33`. The icon has 16, 32, 48 and 256 px, as R3 says; `docs/design/logo.md` 3 plans 20,
    24, 40 and 64 px as well, which Windows asks for at 125 and 150 %, and a `brand --check` that catches a master
    edited without a new render (today the dev builds then embed the old icon until the next `xtask package`). Not an
    R3 defect; keep it on logo B1's list.
15. `packaging/installer.nsi:415`. `$LOCALAPPDATA\cuboid` is also the root of `ProjectDirs::from("", "", "cuboid")`'s
    `data_local_dir` and `cache_dir` (`platform.rs:38`). Nothing uses those today (settings and logs live under
    `%APPDATA%\cuboid`), but a later cache would land in the install folder and keep `RMDir "$INSTDIR"` from removing
    it. `$LOCALAPPDATA\Programs\cuboid` (FOLDERID_UserProgramFiles, where per-user installers such as VS Code go) keeps
    them apart; decide before the first public install, since updates reuse the first folder.
16. `.github/workflows/release.yml`. Run the tag check (`:36-43`) before `cargo install` (`:34`) so a wrong tag fails in
    seconds; set `timeout-minutes`; pass `--prerelease` when the tag has a `-`; attach a `SHA256SUMS` of both files. A
    `workflow_dispatch` trigger that uploads the files as a workflow artifact instead of drafting would let the owner
    try the pipeline without a tag.

## The implementer's choices

1. Custom NSIS template copied from upstream: accepted. A `diff` against the 0.11.8 template (CRLF stripped) shows
   exactly the announced changes plus the header comment: the finish-page box with `MUI_FINISHPAGE_SHOWREADME_NOTCHECKED`
   in place of the desktop shortcut, `AssociateCubik`, the uninstall lines, no desktop shortcut in the silent path and
   the uninstaller. The copy is tied to its source by the version check (`package.rs:269-275`) and the CI install line.
   The box works as an opt-in: MUI2 calls the function only when it is ticked at Finish, and silent and passive
   installs never show the finish page, so they never associate. Findings 1-3, 11 and 12 are in this file.
2. `@ROOT@`/`@VERSION@` substitution into `target/package/Packager.toml`: accepted. Absolute paths make cargo-packager
   independent of its working directory, backslashes become `/` so no TOML escape can break, and the repository file
   stays clean.
3. `name = "cuboid"`: accepted and needed. Without it `cli/config.rs:95-101` fills the name through
   `find_nearset_pkg_name(path)`, which calls `set_current_dir` on the config file itself (`:56`) and fails.
4. `cuboid.portable` only in the zip: accepted. It matches `platform.rs:31-37`; the installed app keeps settings and
   logs in `%APPDATA%\cuboid`, which the uninstaller rightly leaves alone.
5. Windows x64 only: accepted for this release; `package.rs:62-64` refuses elsewhere with a clear message.
6. Placeholders (identifier `org.cuboid.cuboid`, publisher, notices): acceptable for a draft. The identifier and
   publisher must be final before the first published install: the identifier is the shortcut's AppUserModelID
   (unless 11), and its second part names `HKCU\Software\<publisher>\cuboid`, where the next installer looks for the
   previous folder. Notices: 7.
7. No PATH entry: accepted. This NSIS build has `NSIS_MAX_STRLEN=1024` (`makensis -HDRINFO`), so a PATH edit from
   the installer can truncate a long user PATH; the guide and `Snippets` use full paths, and `docs/mcp.md:58` already
   says when typing `cuboid` works.
8. resvg 0.49 (default features off), ico 0.6, winresource 0.1.34 (default features off, Windows build dependency):
   accepted. This is the pair `docs/design/logo.md` 3 names, which meets the "named in the report" condition of
   section 4.1; no SVG parser was in the tree (tiny-skia 0.11 came only through sctk-adwaita on Linux). Licences of the
   15 new lock entries: resvg, usvg, svgtypes, simplecss, roxmltree, data-url, siphasher MIT OR Apache-2.0;
   tiny-skia and tiny-skia-path 0.12 BSD-3-Clause; ico, winresource, float-cmp, imagesize, rgb, pico-args MIT; all on
   the `deny.toml` allow list. None of them ships in `cuboid.exe` (xtask and a build dependency), so they add nothing to
   the notices. tiny-skia is now in the tree twice, a `multiple-versions = "warn"` line for xtask only.
9. `release.yml` (tag check, `cargo install cargo-packager --locked --version 0.11.8`, `xtask package`,
   `gh release create --draft --verify-tag`): accepted in shape, with 6, 7 and 16.

## Checked and sound

- Per user, no elevation: the rendered script defines `INSTALLMODE "currentUser"`, which selects
  `RequestExecutionLevel user` (`installer.nsi:78-80`); NSIS then embeds an asInvoker manifest, so the `setup` in the
  name does not trigger Windows' installer detection. Every write goes to SHCTX after `SetShellVarContext current`, or
  to HKCU by name; HKLM is only read (the WiX loop). The folder is `$LOCALAPPDATA\cuboid`, the shortcut in the user's
  `$SMPROGRAMS`.
- Association keys, apart from 1 and 2: `HKCU\Software\Classes\.cubik` to the ProgID `cuboid.cubik`, its name,
  `DefaultIcon` `<exe>,0` (resource 1 is index 0; the unquoted form parses with spaces), the open command
  `"<exe>" "%1"` quoted on both sides, and `SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST, 0, 0)`. The app takes the
  path as its one positional argument (`lifecycle.rs:52-56`), and R1 made the release program a window program, so a
  double click opens no console. The ProgID removal is unconditional and touches only cuboid's own key; a `.cubik`
  default that points elsewhere is left alone.
- The uninstaller deletes only named files: the rendered script removes `cuboid.exe`, the five resources and
  `uninstall.exe` by name, then `RMDir /REBOOTOK "$INSTDIR\docs"` and `RMDir "$INSTDIR"`, both without `/r`. The only
  `RmDir /r` of the template is the `appdata_paths` block, not emitted because `Packager.toml` sets none; the
  reinstall path's `RMDir $INSTDIR` (`:301`) is non-recursive too. A user-chosen folder with other files keeps them.
  Without the portable marker the app writes nothing into its folder.
- Reinstall and upgrade: the same version overwrites in place ("Add/Reinstall"); a different version runs the old
  uninstaller with `/P _?=<folder>`, then installs; silent runs overwrite in place; the previous folder comes back
  from `HKCU\Software\cuboid\cuboid`. A running `cuboid.exe` is offered for killing in the window installer and in
  the uninstaller.
- Version resource and icon: the staged `cuboid.exe` reports `cuboid | cuboid | 0.1.0 | 0.1.0 | cuboid.exe`,
  `cuboid.com` `cuboid | cuboid command line | 0.1.0 | 0.1.0 | cuboid.com`, the setup `cuboid | Editor for
  Minecraft-style models and voxel art | 0.1.0`. The icons extracted from `target/release/cuboid.exe` and
  `cuboid-term.exe` show the tile `#1a1f1c` and the box `#e3bb3b`. Explorer shows the generic icon for `cuboid.com`
  regardless (`HKCR\comfile\DefaultIcon` is `shell32.dll,2`); harmless. `compile_for` links the resource into the
  named binary only, so test binaries do not carry it. On Windows the scripts rerun only for `build.rs` and the icon
  (and a version change, which changes the package's fingerprint). Elsewhere winresource is not even built: a
  target-specific build dependency is matched against the host.
- `cuboid.ico`: four entries, 16, 32 and 48 px as 32-bit BMP and 256 px as PNG; straight alpha (`demultiply`) as ICO
  expects; the scale comes from `tree.size()`, 256 for `logo.svg` with its 150 viewBox, so every frame fills its size.
- The zip: seven entries under `cuboid-0.1.0/`, sorted, dated 1980-01-01, Deflate, the portable marker last; the
  coordinator's two builds gave the same SHA-256.
- `xtask package` errors: a missing staged file names its path (`:204`), a different cargo-packager version, a failed
  build, a failed packager run and a missing setup are errors, unknown arguments are rejected, and `main.rs` turns
  every `Err` into exit 2. Exception: 5.
- Downloads at package time: the NSIS 3.09 zip and nsis_tauri_utils 0.2.1 are SHA-1 checked by cargo-packager
  (`nsis/mod.rs:30-37`); ApplicationID is not (11).
- `release.yml`: no secret but `github.token`, given to `gh` alone through `GH_TOKEN`; `--draft` and `--verify-tag`;
  the tag compared with the version of `cuboid-app` before anything is uploaded; actions on major tags like `ci.yml`.
- Lock file: 15 additions and the `tiny-skia 0.11.4` qualifiers, nothing else; `cargo metadata --locked` passes.
- Style: LF, no BOM in all seven text files; rustfmt clean; comments in the codebase's voice and pointing at the spec.

## Fixes

Status: 2026-10-29. Engineer: Sonnet. Files: `packaging/{installer.nsi,Packager.toml}`, `xtask/src/package.rs`,
`.github/workflows/release.yml`, both `build.rs`, the install paragraph of `docs/mcp.md`. The installer was not run:
only the template was compiled (`cargo xtask package --no-build`, makensis at `-V2` without a warning).

1. Fixed. `AssociateCubik` keeps the previous default of `.cubik` in `cuboid.backup` (not when it is already
   `cuboid.cubik`, as after a reinstall) and adds `OpenWithProgids\cuboid.cubik`. The uninstaller puts the backup back
   (or deletes the default when there was none) only while the default is still `cuboid.cubik`, then deletes
