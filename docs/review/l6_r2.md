# Review: L6 R2, start-up and idle memory

Status: 2026-10-29. Reviewer: Opus. Scope: the uncommitted R2 of `docs/design/l6_release.md` 3, its Measurements
subsection included: `crates/cuboid-app/src/{startup.rs (new),main,lifecycle,app,frontend,library,render_glue,
io_thread,mcp_render}.rs`, `crates/cuboid-shell/src/{backend.rs (new),contract,event_loop,lib}.rs`. The packaging files
belong to R3. Read against egui-wgpu 0.37.0 (`winit.rs:56-262`, `lib.rs:132-290`, `setup.rs:95-275`), wgpu 30.0.1
(`backend/wgpu_core.rs:692-695`), wgpu-core 30.0.1 (`instance.rs:125-145`, `:198-255`, `:480-632`, `:637-647`,
`device/resource.rs:495-515`), wgpu-hal 30.0.1 (`vulkan/adapter.rs:2311-2323`) and wgpu-types 30.0.1
(`instance.rs:222-332`).
Run on 16 logical cores, 15 GB free on D:: `cargo clippy -p cuboid-shell -p cuboid-app --all-targets -j 4 -- -D
warnings` (clean); `cargo test -p cuboid-shell -j 4` (50 pass); `cargo test -p cuboid-app -j 4` (255 pass, 1 ignored;
`mcp_stdio` 7 pass). Not run: a release build, the GUI, a machine without Vulkan.

Verdict: approved with minor changes; no major. The plan falls back on every error the Vulkan attempt can return (no
loader or ICD, no adapter for the surface, a refused device, no surface format), drops the failed attempt whole before
the next, never tries more than twice, and keeps the device-loss path of R4-A working. Removing
`VALIDATION_INDIRECT_CALL` is safe today. The scripted exit takes the close button's path and cannot lose work. The
trace costs one atomic load per call when off. What is left: the fallback does not cover a first attempt that panics,
which is how a broken driver usually fails; the MCP device kept the flag that R2 removed from the window; the
scripted exit is open to any user who inherits the variable and the property that matters is untested; the pool cap
trades parallel decode for a memory gain nobody measured.

## Major

None.

## Minor

1. `crates/cuboid-shell/src/event_loop.rs:170-191` with `:222-225`. The fallback runs only on an `Err` of the first
   attempt. A driver that gives an adapter and a device but fails to build egui's pipelines does not return one:
   `RenderState::create` builds the egui renderer (`egui-wgpu lib.rs:273`) before the shell installs its logging
   handler (`:238-242`), so the error reaches wgpu's default handler, which panics (`wgpu_core.rs:692-695`). At start
   `Shell::open` is not guarded: the process ends with a crash report and DX12 is never tried. On the recreate path
   (`:505-514`) `guarded` catches the panic around the whole `new_painter`, so again the fallback set is skipped, and
   the shell retries Vulkan every 500 ms until the paint guard quits (8 failures in 30 s, `app.rs:16-17`). Not a
   regression (before R2 wgpu also chose Vulkan, with no fallback at all), but it is the failure mode the fallback is
   for. The retry logic is also the one part of the plan without a test. Fix: extract the retry as a generic function
   and run the first attempt under `guarded` when a fallback exists:
   `fn first_or_fallback<T>(plan: BackendPlan, mut open: impl FnMut(Backends) -> Result<T, String>) -> Result<T,
   String>` (first through `guarded`, on `Err` or panic and `Some(fallback)` warn and call `open(fallback)` once,
   both messages joined as `mcp_render.rs:159` does), with `new_painter` passing a closure over `open_painter`. Tests
   in `event_loop.rs` with a fake opener that records the sets it was given: an `Err` gives one fallback call, a
   panic gives one fallback call, an `Ok` gives no second call, no fallback returns the first error, two failures
   return both messages and make exactly two calls.

2. `crates/cuboid-app/src/mcp_render.rs:135-153`. The MCP device keeps `VALIDATION_INDIRECT_CALL`:
   `without_display_handle` (`:136`) sets `from_build_config().with_env()` (`egui-wgpu setup.rs:247`), so every
   `Gpu::open` in a release build (the first picture, and the reopen after a lost device) still builds the two
   validation compute pipelines through the HLSL compiler, on WARP as well; that is the cost R2 removed from the
   window, on the path whose latency the AI client sees. The server draws with the same `cuboid_render::Renderer`, so
   nothing there draws or dispatches indirectly either. Spec change 2 says "the instance flags" without naming which.
   Fix: one `pub fn instance_flags() -> wgpu::InstanceFlags` in `cuboid-shell/src/backend.rs`, beside the plan and
   with the comment of `event_loop.rs:204-205`, used by `open_painter` and by `open_device`
   (`setup.instance_descriptor.flags = instance_flags();`); the spec names both users.

3. `crates/cuboid-app/src/startup.rs:246-253` with `lifecycle.rs:141`. `CUBOID_EXIT_AFTER` is honoured on every start
   and is documented nowhere a user looks. A leftover value (a `setx` from a benchmark session, a terminal used for
   measuring) closes the editor that many seconds after each start; with unsaved work the "unsaved changes" question
   appears on its own, and the only explanation is an Info line in the log. No work is lost (Checked and sound), but
   the editor looks broken. The property that makes it safe, that the exit asks about unsaved work instead of
   quitting, has no test. Fix: honour the variable only while the trace is on (`--trace-startup` or
   `CUBOID_TRACE_STARTUP=1`), which every scripted measurement uses anyway, e.g. a `startup::tracing()` and
   `app.exit_after = startup::tracing().then(ExitAfter::from_env).flatten();`; log the fire at warn so it reaches
   stderr and `cuboid.com`; add `--trace-startup`, `CUBOID_TRACE_STARTUP` and `CUBOID_EXIT_AFTER` to the logging bullet
   of `architecture.md` 16 (`:1282-1285`, beside `CUBOID_LOG`). Test in `startup.rs`: `state.startup(None)`,
   `run_command(Command::AddElement(ElementKind::Cube))`, `exit.frame`, `state.step`, then `!state.quit` and
   `matches!(state.dialog, Some(Dialog::Unsaved { .. }))`.

4. `crates/cuboid-app/src/io_thread.rs:20-29`. The comment says the pool's work is "bound by the disk", but its loops
   are CPU-bound per-chunk work: decode (`cuboid-fmt-cubik/src/decode.rs:1085-1090`), the chunk table at load
   (`load.rs:604-607`), encode (`encode.rs:436-440`) and the save's chunk records (`save.rs:616-619`). On the
   16-core machine a large voxel open, save or autosave now has 4 workers instead of 15. The gain is 11 idle rayon
   workers, a few committed stack pages and a deque each, likely well under 2 MB of working set; the Measurements
   table does not isolate it (157 to 133 MB is the backend change). Spec 3.2 keeps "only changes the trace proves", and
   the owner's order puts performance before RAM. Fix: measure, release build, the open and the save of a large voxel
   `.cubik` (a 512 cubed world) with 4 and with 15 workers, and the idle working set of each; record both in
   Measurements. If the open slows noticeably for a small gain, raise the cap (for example `(cores - 1).clamp(2, 8)`);
   otherwise keep 4 with the numbers as the reason. Correct the comment either way.

## Nit

5. `crates/cuboid-shell/src/event_loop.rs:274`. After a start on the fallback set, each device loss tries Vulkan
   again first, one loader start and one failure on the UI thread per recreate. Fix: keep the backend that opened the
   painter in `Win` (`gpu.adapter.get_info().backend`) and recreate with that set first.

6. `crates/cuboid-shell/src/backend.rs:49-52`. The fallback `DX12 | GL` creates both instances, so a machine without
   Vulkan also loads its GL driver next to DX12, which wgpu then sorts below a hardware DX12 adapter. Fix, if a
   no-Vulkan machine is ever measured: a chain `[VULKAN, DX12, GL]` in place of `first` and `fallback`.

7. `crates/cuboid-shell/src/backend.rs:49-52`. Before R2 the device type sort ran across all backends; now a
   CPU-type Vulkan adapter (a lavapipe or SwiftShader ICD) wins over a hardware DX12 GPU. Rare on Windows. Fix, with
   the native adapter selector the spec lists under "Not changed": refuse a `DeviceType::Cpu` adapter in the first
   attempt while a fallback exists.

8. `crates/cuboid-app/src/startup.rs:275`. `now + self.delay` panics for a delay close to `u64::MAX` seconds (for
   example `CUBOID_EXIT_AFTER=18446744073709547520` on a machine up more than an hour), and `ExitAfter::frame` runs
   outside the frame guard (`app.rs:127`). Fix: `now.checked_add(self.delay)`; on `None` set `fired`, warn, never quit.

9. `crates/cuboid-app/src/startup.rs:178-179`. With `--debug --trace-startup` every phase is printed twice on stderr:
   the logger echoes Info lines in debug (`logging.rs:178`) and the trace writes the raw line. Fix: pass the echo flag
   to `startup::init` and skip the raw write when the logger echoes.

10. `crates/cuboid-render/src/contract.rs:22-25` and `event_loop.rs:204-207`. Tier A (`architecture.md:1083-1086`)
    plans `multi_draw_indirect` from a CPU-filled buffer; without wgpu's validation a bad range reads past a pool
    buffer (at worst a lost device) instead of being skipped. Fix: say on `indirect_execution` that the instances run
    without the indirect validation, so tier A clamps each range to its pool or turns the flag back on; and keep the
    flag in debug builds (`if cfg!(debug_assertions)`), which nobody measures and which then catch a bad range.

11. `docs/design/l6_release.md:45-46` and `crates/cuboid-app/src/startup.rs:1-2` say "since process start"; the code
    counts from the first line of `main` (`main.rs:61`), so the loader's pre-`main` time is outside every number,
    the cold 640 ms included. Fix: say "since the start of `main`", and bound the rest once from outside
    (`Measure-Command { Start-Process cuboid.exe -Wait }` with `CUBOID_EXIT_AFTER=0`). The table also lacks the final
    configuration: add the row Vulkan first with fallback (630 ms warm, 640 cold, 133 MB, 34 threads) with its private
    bytes, and say which rows include the pool cap.

## Checked and sound

- Fallback triggers. No Vulkan loader or ICD: wgpu-core skips a backend whose `init` fails (`instance.rs:132-145`),
  and `create_surface` with no backend returns `FailedToCreateSurfaceForAnyBackend` (`:243-246`), so `set_window`
  fails and the DX12 and GL set runs. A Vulkan adapter that cannot present to the window is dropped by
  `request_adapter`'s surface check (`:527-545`), giving `NotFound`. A refused device gives `RequestDeviceError`; no
  usable surface format gives `NoSurfaceFormatsAvailable`. All four reach `new_painter` as `Err`. A WARP-only machine:
  without `force_fallback_adapter` wgpu-core keeps CPU adapters and sorts them last (`:566-600`), so the fallback opens
  WARP, or a GL 3.3 driver first when there is one (type Other). The non-conformant Vulkan of Windows on ARM (Dozen) is
  hidden by wgpu-hal (`adapter.rs:2311-2323`), so it falls back too. `WGPU_BACKEND` wins with no fallback; an empty
  list is ignored.
- Nothing half-built. The failed attempt's painter (instance and surfaces) is a local of `open_painter`, dropped at the
  `?`; the adapter, device and surface of a failed `RenderState::create` are its locals. `Painter` has no `Drop` and
  does not touch the egui context; `set_max_texture_side`, the `egui_winit::State` and `Win` are made only after
  success. The window keeps at most a Vulkan surface that never had a swap chain (it is configured in
  `install_surface`, after the render state exists), destroyed before DX12 attaches one.
- No loop. `new_painter` makes at most two attempts; a failed recreate waits `PAINT_RETRY` and the paint guard ends
  the program after 8 failures in 30 s.
- R4-A. `recreate_gpu` drops the old painter first, then goes through the same plan; `follow_device`
  (`render_glue.rs:73-89`) rebuilds the renderer with the new caps when the backend changed, `send_egui_textures`
  re-uploads the atlas, and egui's renderer is built for the new surface format.
- `VALIDATION_INDIRECT_CALL`. No `draw_indirect`, `multi_draw_indirect` or `dispatch_workgroups_indirect` in
  `crates/`, and none in egui-wgpu 0.37.0. In release `from_build_config` is that flag alone (`wgpu-types
  instance.rs:268-274`); wgpu-core builds the validation pipelines at device creation only with it
  (`device/resource.rs:500-515`). The flag's `u32` clamp of `max_buffer_size` (`instance.rs:637-647`) applies to the
  adapter limits; the device keeps the requested defaults (256 MiB), which is what `elements.rs:106` and
  `voxels.rs:196` read. `WGPU_VALIDATION_INDIRECT_CALL=1` turns it back on (`.with_env()` after the removal).
- Pool. Each `IoThread` injects one task at a time through `install`, so at most two injected tasks run; two workers
  give each its own. A parallel loop inside a task runs on the pool, and a `join` nobody steals runs inline, so no pool
  size of one or more deadlocks. No job blocks on another job's result: the only blocking waits are the file dialog
  threads, outside the pool. The R4-B guard `a_long_job_of_one_io_thread_does_not_hold_the_jobs_of_another` still
  holds, and the clamp keeps two workers on one to five cores.
- Phase hook. Off, each call is one `OnceLock` load (`startup.rs:174`), with `Instant::now` only after it; four calls
  per frame. The associated function with `where Self: Sized` keeps `ShellApp` object safe for `headless.rs`
  (`contract.rs:325`). Phases recorded only the first time, so the second attempt of a fallback does not overwrite
  them, and the fallback's warn line reaches stderr through the logger (`logging.rs:178`).
- Scripted exit. It pushes `Intent::Quit`, the close button's intent (`app.rs:90`). `flows.rs:561-595`: a running save
  is waited for and the quit asked again; a running open is cancelled (nothing to lose); unsaved work opens the
  question; an open question drops the quit and `fired` stops a repeat. With the recovery dialog up and a clean
  document `finish_quit` purges only its own session (`backup.rs:302-307`), so a crashed session's autosaves stay on
  offer. File dialogs run on their own thread, so the exit can come during one; with unsaved work it asks. The clock
  starts at the first frame with no document job and an empty inbox, and the frame asks a wake-up at the deadline.
- Trace output. A release `cuboid.exe` started from Explorer has no stderr: std drops the writes, and the lines are in
  `<data>/logs/cuboid.log` at the default Info level (not with `CUBOID_LOG=warn`). Through `cuboid.com` the stderr
  pipe is relayed (`cuboid-term/src/main.rs:47-56`) and the shell waits for the editor. Lines are written under the
  trace lock, so phases from the library thread keep their order; the lock is taken before the logger's and never the
  other way.
- Tests. `backend.rs`: the plan per system and target, the user's choice, the empty list. `startup.rs`: one line per
  phase, the summary once in reached order, the document phase only with a file, the incomplete summary at exit, the
  seconds parser with its bad inputs, the clock waiting for the open, a zero delay, and two tests on a real `State`
  (an idle start quits through the normal quit; the delay does not run while the named file opens).
  `io_thread.rs`: the size table and the live range. `lifecycle.rs`: the new flag is parsed.
- Spec. The phases match 3.1 (device, egui renderer and surface are one egui-wgpu call, said so in `ShellPhase::Gpu`).
  The measurements meet both targets with Vulkan first, the rows support the choice, D-R3 applies, and the global
  rayon pool is indeed not built on an empty start (its loops are the voxel ones: `extract.rs:806`, `world.rs:165`).

## Fixes

1. Fixed. `first_or_fallback` in `event_loop.rs` runs the first attempt under `guarded` and the fallback once on an
   `Err` or a panic, joining both messages; `new_painter` is one call to it. Five tests with a fake opener: ok, error,
   panic, no fallback (error and panic), two failures.
2. Fixed. `instance_flags()` in `backend.rs` (comment moved there, one test), exported by the shell and used by
   `open_painter` and by `mcp_render::open_device`; the spec names both users.
3. Fixed. `ExitAfter::from_env` is read only when `startup::tracing()`; the fire logs at warn; the variables are in
   `architecture.md` 16 and the spec; test `a_dirty_document_gets_the_save_question_instead_of_quitting`.
4. Fixed as the coordinator decided. `pool_size` is `cores.saturating_sub(1).clamp(2, 8)`, the comment says CPU-bound,
   the test table follows. Not measured here (no release build); the spec says the final pool is unmeasured.
5. Not fixed. A device loss after a fallback start tries Vulkan first again; a rare path, one failed loader start.
6. Not fixed. The chain `[VULKAN, DX12, GL]` waits for a measurement on a machine without Vulkan.
7. Not fixed. A CPU-type Vulkan adapter over hardware DX12 needs the native adapter selector, listed as not changed.
8. Fixed. `step` uses `checked_add`; a delay beyond the clock warns, sets `fired` and never quits; test added.
9. Fixed. `startup::init` takes the echo flag and the raw stderr line is skipped when the logger echoes Info.
10. Not fixed. No indirect call exists yet; the note and the debug-build flag belong to the tier A package.
11. Fixed in part. Wording corrected in `startup.rs` and the spec, the final row added (630 ms warm, 640 cold, 133 MB,
    34 threads). The private bytes of that row and the pool of each row were not recorded, so the spec says so; the
    outside bound of the loader time is described, not measured.
