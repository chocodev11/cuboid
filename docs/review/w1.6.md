# W1.6 review (fail)

W1.6 gives one apply path for open, merge, restore and paste, plus capture by category, the record normal form and a literal reference twin. The structure is sound. Everything is checked before the document changes. Fixed points keep their `Arc`. ObjIds and display ids follow arch 8.2. The twin is independent of the fast path: it uses records, the W1.5 setters and the full voxel writer, never `normal_form` or `VoxelWorld::from_snapshot`. The proptest runs 10^4 cases of 1 to 3 rounds and includes failing snapshots. All checks pass: `cargo clippy -p cuboid-model --all-targets -- -D warnings` (also clean with `--features reference`), `cargo test -p cuboid-model` (152 passed), `cargo fmt -p cuboid-model -- --check`, `cargo xtask ledger --wp W1.6` and `cargo xtask layering`. The package still fails on four items. Open resets the view and the blueprint, which the spec says it keeps. A fixed voxel resolution cap breaks the reader rule of native 4.7. Two mesh rules of the record shape are missing: the primitive tint, and the packing of sub-mesh colours. In two of these, the ledger calls the spec open when it is settled.

## Blocking

1. `crates/cuboid-model/src/apply.rs:431-432` (in `reset_scene`; also the `ApplyMode::Open` doc at lines 30-33 and the ledger header at `parity/ledger/w1.6.toml:9-12`). Open resets `doc.view` and `doc.blueprint` to their defaults. Native 6.1 lists what Open resets: model properties, model box, origin, elements, meshes, voxels, selection, voxelisation, display preview, panels, UI state, paint state and undo. It lists neither the view state nor the blueprint. Native 4.1 says a file without `vp` leaves the view state untouched, and a file without `bp` leaves the blueprint untouched. Native 4.3, native 6.3 and app 6.6 say `gu` and `gl` are ignored on load, so the live UV step and "Large" stay. Scenario: the user sets the UV mapping snap to 1/8 and turns Large on, then opens a Cubik file. Cubik keeps both. The port shows 0.5 and Large off. A hand-made file without `vp` or `bp` also loses the live cameras and blueprint. The rotation-equality rule for `bp` is also affected: it compares against (0,0,0) instead of the live blueprint rotation. The `tested` entry `native.6.1.open-and-merge` does not cover this, and the header note misquotes 6.1. Fix: make `reset_scene` keep `doc.view` and `doc.blueprint`. Correct the doc comment and the ledger note. Add a test where Open keeps `uv_step`, `large_grid` and the blueprint when the file has no `vp` or `bp`.

2. `crates/cuboid-model/src/apply.rs:21-23` and `:225-230` (`MAX_VOXEL_RES` = 254, `check_resolution`; ledger `native.6.3.vx-new-world-limits` at `w1.6.toml:194-201`). The apply path refuses every resolution above 254. Native 4.7 says readers MUST accept any R >= 1 within a configurable memory limit. Arch 12.3 puts the check against a memory budget in the reader. 254 is neither configurable nor a memory limit, and the ledger note admits the conflict while filing it as `unverified-spec`. Scenario: a file with R = 300 and a few hundred voxels fits any sane budget. W1.7 decodes it, but `apply_document` returns `VoxelResolution(300)`. W1.7 cannot honour 4.7 without changing this crate. Fix: drop the fixed cap. Keep `res >= 1` and the slot-count check, using checked arithmetic for `3 * res` and `n * n * n`. Leave the memory budget to the reader, or take the limit as a parameter that W1.7 sets. Keep `unverified-spec` only for the setup corners of a loaded world.

3. `crates/cuboid-model/src/normal_form.rs:76-88` (`mesh`) and `crates/cuboid-model/src/reference.rs:148-158` (`create_mesh`). The ledger entry `tools.7.10.mesh-tint-on-restore` (`w1.6.toml:361-368`) says the spec does not say whether undo resets the tint. The spec does settle it for primitives. Tools 6.1 says the material colour (tint) is not persisted for primitives (QUIRK). Tools 6.2 says restoring a primitive mesh record (load, undo, redo, paste) runs the builder and then applies the record fields: position, origin, offset, size, rotation, hidden, locked, label, type, paint texture and bounds. The tint is not among them. Native 4.6 has no tint key, and arch 9.1 says snapshots have the record shape. The port restores and pastes the captured tint. Scenario: tint a cube primitive red ("Set mesh tint"), drag it, then press Ctrl+Z. Cubik rebuilds the cube with the builder's tint. The port shows it red. A pasted copy of a red primitive behaves the same way. The twin cannot see this, because it clones the whole mesh as its template. Fix: in `normal_form::mesh`, give every non-`Custom` mesh the tint of a freshly built primitive. Build the twin's mesh from a fresh object of the kind plus the record keys only. Split the ledger entry: make the primitive tint `tested`, and keep `unverified-spec` only for what the spec leaves open (drag sensitivity, gizmo values and import offset of imported meshes). Cite tools 3.1, 6.1 and 6.2 instead of tools 7.10.

4. `crates/cuboid-model/src/normal_form.rs:76-88` (`mesh`). Arch 9.1 lists colour packing (native 4.10) as part of the record normal form for restore and paste. Native 4.10 has its own row for sub-mesh colours: each channel is multiplied by 255, truncated and kept modulo 256 with no clamp, and a zero alpha gives 0. The port packs element colours only. It copies sub-mesh colours unchanged, and no ledger entry records the gap. Scenario: an imported mesh has a sub-mesh colour of 0.5. After the undo of any meshes entry, Cubik holds 127/255 (about 0.498) and the port holds 0.5. A channel of 1.2 wraps to 50/255 in Cubik, while the port keeps 1.2. Fix: in `normal_form::mesh`, map each sub-mesh colour through `pack::submesh` and `pack::unpack_submesh`, and copy the mesh only when the result differs. Keep packed sub-mesh colours in the twin's mesh record. Add a test and a ledger entry.

## Nonblocking

- Several entries are `unverified-spec` even though the spec or the architecture settles them and the code already agrees. They are underclaims, not overclaims. `native.4.10.element-colour-on-restore` and `native.4.4.uv-on-restore` are settled by arch 9.1, which names colour packing and UV clamp and fold. `native.6.3.plane-size` is settled by 6.3: creation sets the thin axis to 0.001 "first", then sizes apply as stored. `native.6.3.rer-source` is settled by 6.3, which names `mp.g.rer`, and EditEnv mirrors `g.rer`. `tools.11.3.paste-uv-snap` is settled by 11.3: "the stored uvSnap is cleared first". These can move to `tested`.
- These entries are open in the spec and are fine as `unverified-spec`: `tools.15.3.view-properties-restore` (15.3 has no step for it, and only "Reset camera" uses the category), `native.6.1.merge-retention`, and the setup-corner half of `native.6.3.vx-new-world-limits`. `arch.8.2.highlight-after-apply` is backed by the arch 8.7 invariant that the selection refers to live objects only.
- `capture` applies the save normalisations to undo and clipboard snapshots as well. That is harmless for `gu` and `gl`, which the `vp` rule ignores, and for quotes, which the live strings never hold. For `md` it changes undo: a zero display scale comes back as 0.0001 after an undo of "Edit display settings". The spec names this rule only for the save. Note it in the ledger, or apply the `md` rule to save captures only.
- Tools 15.3 restores textures before elements. The port uses the file order of native 6.2. Nothing in the port reads textures while elements are applied, so there is no visible effect. A comment would help.
- The twin builds every object from a full clone of the snapshot object (`template`). It therefore cannot detect losses outside the record keys, such as the mesh tint, sub-mesh colours, normalisation factor, import offset or element kind. Blocking items 3 and 4 slipped through this way.
- The proptest generates only cube elements and voxel resolutions up to 12, and it clamps the blueprint size only through one tweak. Its dirty-subset check is always true, because the fast path dirties every slot. Plane elements and primitive and custom mesh records would cover the size and tint rules.
- `LoadedDoc.voxel_replay` is ignored silently when `sections` lacks the voxel category. The doc comment states this as a loader rule, so `validate` could refuse such a source.
- Paste and Merge do not check for repeated ids. That is harmless, because both allocate fresh ids.

## Integration notes

- W1.7 load: hand over only the sections the file has. An absent or null `vx` becomes the voxel category with `Some(None)`. Canonical voxel records go in a `VoxelSnap`; out-of-order or repeated records go in `voxel_replay`. Lists use `ListSnap::fresh`, and meshes carry the permissions of their kind. Set `mp.sp` after Open, never after a failed load. The reader enforces the resolution budget (arch 12.3).
- W1.7 save: capture the cameras into `doc.view` and set `mp.sp`, then call `capture` with all categories. The writer owns colour packing, folded UV, `fp` and `cs`, `me` and `sm` of primitives, the blueprint keys and float widening, as the `native.5.3` ledger note says.
- W1.7 `.cub` (native 9.5) must not go through the record normal form. It keeps transparent element colours until the save and unclamped UV, and it sets the model box without `g.mb`. Run Open with an empty section set for the reset, then build through the setters. `set_model_box` always writes `g.mb`, so a raw model box setter would come from W1.5.
- W2.1 history: `capture_current` is `capture(doc, sel, CaptureScope { categories, selection_only: false })`, and undo or redo is `ApplyMode::Restore(categories)`. After every apply, feed the elements of `report.created` to the start queue, refresh `EditEnv::restrict_rotations` from `doc.props`, and copy the `doc.view` cameras into the live view set when the view category was applied. Apply never touches the dirty flag.
- W2.1 clipboard: copy is a selection-only capture of `OBJECTS`. The paste offset is the blueprint position now minus the copy anchor. Voxel paste is separate. The element popup "Clone" (tools 10.2) copies the float colour and every property, so it should not reuse `ApplyMode::Paste`, which packs colours, requantises rotations and restores the blueprint.
- The blueprint has no `ObjId` and no journal entry, so scene sync must watch the blueprint itself (a W1.5 contract choice).
- `apply_reference` and `documents_match` build under `--features reference`, so W2.1 can reuse them for its history proptest.
